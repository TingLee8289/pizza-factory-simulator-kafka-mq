Architecture · Event Streaming

Kafka Core Architecture & Log Commit Model

Kafka 的本質是一本只進不出的分散式日誌（Commit Log）。訊息讀取後不會被刪除，消費者透過各自獨立的書籤（Offset）自由回溯或即時追蹤事實事件。

Storage Architecture

1. Append-Only 與零拷貝效能

Kafka 寫入訊息純粹往硬碟尾端追加（Append-Only Sequential Write），避開隨機 I/O 損耗。搭配作業系統頁面快取（PageCache）與 Sendfile 零拷貝技術，能達到每秒百萬級事件吞吐量。

Smart Consumer Pattern

2. 愚蠢的 Broker、聰明的消費者

Broker 不負責維護訊息是否已被哪些消費者看過。Consumer 自己將進度（Offset）記錄於特殊的 __consumer_offsets 主題。這意味著消費者隨時可以「倒帶歷史」重新跑整份分析模型。

Fab Domain Context

3. 本專案中的「事實串流」

在晶圓 / 披薩產線中，機台完成加工發出 op_completed 是不可抹滅的事實。排程器立即響應此事件指派下一站，同時 KPI 模組與即時儀表板也能並行讀取，實現高度微服務解耦。

Producer Delivery

4. produce 與 flush：先確認送達再 ack

produce() 只是把訊息放進 Producer 本機的送出佇列，並不代表 Broker 已收到；flush() 會阻塞等待佇列清空，直到每筆訊息都取得送達回報（delivery report）。本專案搭配 acks=all 與 idempotent producer，站點必須先 flush 成功，才能 ack RabbitMQ 的 job；若在兩步之間崩潰，job 會被重送，造成重複事件，因此下游消費者要以 event_id 與 (order_id, step, visit) 去重（至少一次語意）。送不出去時（flush 逾時或回報錯誤）則不 ack，讓 job 回到佇列。

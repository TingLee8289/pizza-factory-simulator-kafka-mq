RabbitMQ Core Architecture & Topologies

生產者永遠不直接對佇列寫入，而是發送至 Exchange；由 Exchange 依據 Binding 規則分發給佇列，消費者處理後回傳 ACK 釋放訊息。

Core Distinction

1. Exchange 不是 Broker

Broker 是整座運行中的伺服器實例（包含連接埠、虛擬主機、權限與所有 Queue）。而 Exchange 只是 Broker 內部的「無狀態分揀機關」，它接收訊息並以微秒級速度依規則複製轉發至各 Queue。

Decoupling & Routing

2. 生產者完全不知道 Queue 的存在

Producer 只需認明 Exchange 與貼上 Routing Key（如 order.created），不需要知道下游有幾個 Queue 或微服務。系統可隨時熱拔插新增下游消費者，完全不必更動生產端程式碼。

Reliability Contract

3. ACK 機制確保訊息不丟失

當 Consumer 取出訊息時，Queue 會將其標記為 Unacked。只有在 Consumer 順利完成業務邏輯並送回 ACK 時，Queue 才會將訊息刪除。若 Consumer 途中當機，訊息會自動放回佇列供其他實例處理。

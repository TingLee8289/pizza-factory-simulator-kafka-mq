Architecture · Phase 3 Full Line, Scheduler and Order Generation

Phase 3 全產線:指令從 RabbitMQ 往下,事實從 Kafka 回來,Scheduler 用 credit 逐站放行

Credit 迴路

Scheduler 每次只放行 1 個 job 給某一站(credit = prefetch 1)。該站的 op_completed 寫進 Kafka 後,credit +1,Scheduler 才放行下一個,所以每站同時最多一個待處理指令。

Bake 是瓶頸

bake 的處理時間最長。工作在它前面排隊(buffer 不限、不阻塞),其他站在等它。排隊發生在 Scheduler 的 backlog,不在 RabbitMQ,所以排程規則才有選擇空間。

可觀察、可重現

order.lifecycle 記錄每張訂單的 created → released → in process → completed。訂單產生器用 seed 和到達率,同樣設定產生同樣的訂單序列。
